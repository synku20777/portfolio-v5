  <section class="mb-16 prose prose-neutral max-w-3xl dark:prose-invert">
    <h2>Make the data flow understandable first</h2>
    <p>The parent component owns the task list. A typed Task describes the title, categories, description, deadline, and priority; the form and cards receive data and callbacks through props. Saving an edit updates the corresponding record in the same list rather than creating an independent copy of the task.</p>
    <p>The implementation includes title and deadline requirements, an edit mode that reuses the form, and confirmation before deletion. These are small but concrete examples of connecting interface states to record changes.</p>
  </section>

      <h2>A shared learning project</h2>
      <p>The report credits the group collectively with coding, research, React experiments, and design implementation. After earlier difficulties with branches, one person maintained the working codebase while the team contributed locally. I present this as collaborative development rather than sole ownership of the application.</p>
      <p>The useful learning outcome was understanding how parent state, typed props, and callbacks connect a form to a list of records.</p>

      <h2>What this version demonstrates</h2>
      <p>The inspected implementation supports creating, editing, and deleting tasks, category filtering, and priority/deadline controls. Tasks live in component state in this version; persistence, completion-status controls, reminders, and a more polished interface remain extensions.</p>
      <p>The report recommends React Testing Library checks for creation, filtering, and updates. It does not document a completed automated suite or measured usability results, so those are not included as outcomes.</p>
