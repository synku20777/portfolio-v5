When I rebuilt my portfolio, I had a choice: Next.js, Remix, plain HTML, or Astro. I went with Astro, and React islands are a big reason why.

## The problem with full-React sites

A portfolio is mostly static content — text, images, case studies. Shipping a full React runtime for that is wasteful. Users pay the cost in bundle size and hydration time for interactivity they'll never use.

## Islands to the rescue

Astro's island architecture flips the model: **everything is static HTML by default**. You opt *into* JavaScript only where you need it.

On my site, only three things are interactive:
- The **navigation dock** (`client:load` — needs to be ready immediately)
- The **footer** (`client:visible` — only hydrates when scrolled into view)
- The **theme toggle** (part of the dock)

Everything else — case studies, the about section, the works grid — is zero-JS static HTML.

## The result

My portfolio loads fast. Really fast. The initial HTML is tiny, fonts load early via `preload`, and images lazy-load. The Lighthouse scores speak for themselves.

## When to reach for React

I use React islands when I need:
- **State management** — toggles, filters, interactive elements
- **Animation** — Framer Motion components that need JS
- **Third-party libraries** — anything that expects a React runtime

For everything else, `.astro` components do the job with zero client-side cost.

---

If you're building a content-heavy site and reaching for Next.js by default, give Astro a look. You might be surprised how little JavaScript you actually need.
